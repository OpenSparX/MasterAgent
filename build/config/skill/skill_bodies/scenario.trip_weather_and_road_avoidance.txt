【适用场景】
当用户在行程中强调下雨、积水、拥堵、高架、学校门口、夜路等风险因素时，使用本 Skill。

【触发信号】
用户表达包含但不限于：
1. 别走积水那边。
2. 今天不走高架。
3. 避开学校门口那段。
4. 雨太大，稳一点。

【目标】
围绕风险规避诉求，输出更稳妥的路线建议、避让策略或澄清问题。

【输入关注点】
1. 目标地点是否明确。
2. 用户想规避的风险类型是什么。
3. 用户更重视安全、稳定还是通行效率。
4. 是否存在特定路段、区域或道路类型限制。

【执行步骤】
1. 提取目标地点与风险关键词。
2. 识别用户明确要求规避的道路类型或区域。
3. 如果规避对象不明确，先追问最关键的限制条件。
4. 给出“风险优先”路线建议，必要时说明可能变慢。
5. 若 query 同时包含时效要求，则提示安全与时效之间的取舍。

【分支处理】
1. 用户明确说“慢一点也行”时，可更明显偏向稳妥路线。
2. 用户明确说“不走高架/不走某段路”时，应把该限制视为硬约束。
3. 若用户只表达“危险”“不想走那边”，但未说明具体对象，则优先澄清。

【约束】
1. 不承诺不存在风险，只能给出更稳妥的建议。
2. 不在没有地点与道路信息时假装已经完成规划。
3. 安全性优先于激进效率。

【输出要求】
输出至少包括：
1. 识别到的风险偏好。
2. 建议规避的对象或路径倾向。
3. 可能的时间影响。
4. 仍需确认的信息。

【终止条件】
当已经输出风险规避建议或必要澄清后结束。

【失败与回退】
如无法判断目标地点或规避对象，则回退为最小必要澄清。
