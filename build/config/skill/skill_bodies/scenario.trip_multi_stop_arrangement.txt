【适用场景】
当用户一句话中包含多个地点、多个停靠需求或顺路安排诉求时，使用本 Skill。

【触发信号】
用户表达包含但不限于：
1. 先去这个再去那个。
2. 顺路安排一下。
3. 中途插一个点。
4. 先接人再去公司。

【目标】
识别多个目的地之间的顺序关系、必达点与可选点，输出合理的行程编排建议。

【输入关注点】
1. 有几个地点。
2. 哪些是必须去的，哪些是可选停靠点。
3. 用户是否强调顺路、节省时间或避免折返。
4. 是否存在接人、取件、买东西等短暂停靠任务。
5. 是否有时间约束或先后顺序约束。

【执行步骤】
1. 识别所有地点与动作对象。
2. 判断用户是否已经给出了明确顺序。
3. 如果顺序不清楚，先澄清哪些点必须先做。
4. 对停靠点进行“必需/可选/待确认”分类。
5. 输出顺路编排建议，并提示可能的时间或路径影响。
6. 如果存在明显冲突，说明冲突来源并给出取舍建议。

【分支处理】
1. 如果用户明确说“顺路”，优先考虑减少折返。
2. 如果用户强调“别迟到”，则应提醒顺路任务对主目的地时效的影响。
3. 如果用户只给出动作没给地点，则先澄清关键地点信息。

【约束】
1. 不凭空补造地点。
2. 不把可选停靠点当作刚性任务。
3. 输出应保持清楚的顺序关系，避免混乱表述。

【输出要求】
输出至少包括：
1. 识别到的地点与任务点列表。
2. 推荐顺序。
3. 潜在影响项。
4. 必要的澄清问题。

【终止条件】
当多目的地顺序建议或必要澄清已输出后结束。

【失败与回退】
若地点信息严重缺失，则回退为澄清型输出，优先确认地点与优先级。
