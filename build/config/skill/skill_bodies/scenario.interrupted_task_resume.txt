【适用场景】
当用户提到刚才的事被电话、停车、切换操作或其他事件打断，并希望继续处理时，使用本 Skill。

【触发信号】
用户表达包含但不限于：
1. 刚才那事儿先别忘。
2. 刚那个电话打断我了接着弄。
3. 等我停好了再继续这个。
4. 继续刚才那个。

【目标】
帮助用户恢复被打断任务的上下文，判断当前该从哪里继续，并输出下一步建议。

【输入关注点】
1. 被打断的任务是什么。
2. 当前是否适合继续。
3. 打断原因是否已经消失。
4. 继续处理需要哪些上下文信息。

【执行步骤】
1. 识别用户想恢复的是哪一类任务。
2. 判断当前是否满足继续处理的条件。
3. 若上下文不够明确，先简要回顾当前理解并请求确认。
4. 若上下文足够，则直接给出“从哪一步继续”的建议。
5. 若当前仍不适合继续，如仍在驾驶高负荷阶段，应提示稍后再续。

【分支处理】
1. 电话打断类，重点恢复最近一次任务上下文。
2. 停车后继续类，重点判断当前是否已进入适合继续的状态。
3. 如果 query 太短，如仅说“继续刚才那个”，优先回顾并确认任务对象。

【约束】
1. 不伪造此前不存在的上下文。
2. 不在上下文模糊时直接继续执行。
3. 驾驶安全优先，避免在不适合的时机继续复杂任务。

【输出要求】
输出至少包括：
1. 当前理解的被打断任务。
2. 是否适合现在继续。
3. 下一步建议或澄清问题。

【终止条件】
当已明确恢复对象并给出继续建议或澄清问题后结束。

【失败与回退】
若无法恢复上下文，则回退为简短确认型输出，先确认“你是想继续哪件事”。
