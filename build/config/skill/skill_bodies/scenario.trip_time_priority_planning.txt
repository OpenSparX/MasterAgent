【适用场景】
当用户关注是否来得及、几点出发合适、如何避免迟到、是否需要提前离开时，使用本 Skill。

【触发信号】
用户表达包含但不限于：
1. 去某地别迟到。
2. 来得及吗。
3. 我几点走合适。
4. 先去接人再去公司还赶得上吗。

【目标】
结合当前时间、目标地点、可能的停靠点与时间约束，给出时效优先的出发建议、行程安排建议或澄清问题。

【输入关注点】
1. 目标地点是否明确。
2. 是否存在到达截止时间或强时间约束。
3. 是否包含中途停靠点或接送任务。
4. 用户更在意准时、稳妥还是舒适。
5. 是否存在天气、拥堵或特殊路况提示。

【执行步骤】
1. 提取目标地点、截止时间、是否有中途停靠点。
2. 如果目标地点或时间约束不明确，优先提出最小必要澄清。
3. 判断当前 query 的核心诉求是“是否来得及”还是“给出出发建议”。
4. 在已有信息下，生成保守型时间建议，优先避免迟到。
5. 如果存在中途任务，提示其对整体时效的影响。
6. 输出建议时，区分“可以直接建议”和“需要补充信息后再判断”。

【分支处理】
1. 如果用户明确说“别迟到”，则优先保守估计，倾向于更早出发。
2. 如果用户包含多个地点，则提示是否需要顺路编排。
3. 如果用户同时提到天气或特殊路况，则建议转交到风险规避类场景综合处理。

【约束】
1. 不在信息不足时伪造精确到分钟的承诺性结论。
2. 不默认存在未给出的地点、时间或约会对象。
3. 驾驶安全优先，不因赶时间而输出明显激进的建议。

【输出要求】
输出至少包括：
1. 当前理解到的目标地点与时间约束。
2. 是否需要立即出发或建议提前量。
3. 是否存在影响时效的额外因素。
4. 若信息不足，明确指出需要补充什么。

【终止条件】
当已经给出明确的时效判断、出发建议或澄清问题后结束。

【失败与回退】
如果无法识别目标地点或时间约束，则回退为澄清型输出，仅询问完成判断所必需的信息。
