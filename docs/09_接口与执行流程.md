# 接口与执行流程

## 1. 公共调用上下文

跨模块调用携带 `CallContext`：

- `caller`
- `request_id`
- `trace_id`
- `principal_id_hash`
- `priority`
- `deadline_mono_ns`
- `producer_endpoint_id`
- `producer_epoch`
- 可选授权引用

同进程调用也必须通过 caller whitelist。业务 payload 不能声明自身调用方或提升优先级。

## 2. 直接回复

```text
Interaction -> AgentService -> Preprocess/Memory
            -> Skill/Intent -> REPLY|ASK|FAIL
            -> AgentService -> Interaction
```

不创建 DAG，不进入 Orchestrator，不执行 Tool。

## 3. 确定性原子任务

```text
Interaction -> AgentService -> Intent deterministic adapter -> PLAN
            -> Orchestrator -> AtomicService
            -> MCP Provider -> completion/reconcile
            -> Orchestrator -> AgentService -> Interaction
```

## 4. 两阶段查询任务

```text
Intent -> First Inference -> QUERY_BATCH
       -> bounded query execution -> frozen EvidenceBundle
       -> Second Inference -> PLAN|ASK|REPLY|FAIL
```

第二阶段不能再次查询。若输出 `PLAN`，节点 executor 使用 `agent_dispatch` 或 `atomic_service`，不能使用未注册名称。

## 5. 调用方归属

| 被调用接口 | 允许的主要调用模块 |
| --- | --- |
| AgentService.runTurn | InteractionIngress |
| IPreprocess.process | AgentService |
| IStateQuery.getCapabilities/queryRuntimeState | AgentService |
| Prompt.buildPrompt/selectTemplate | IntentSupport、模块测试或受信管理面 |
| Skill.routeSkills/getSkillDetail | IntentSupport、模块测试或受信管理面 |
| Inference.submit/query | Intent、Orchestrator 或受信子调用边界 |
| Orchestrator.submit | AgentService |
| Atomic.submit/query | Orchestrator 或已验证父级子调用 |
| AgentDispatch.submit/query | Orchestrator 或已验证父级子调用 |
| DataLog.append | 已登记的业务模块 |
| Exception.report | AgentService、PreprocessingEngine 等已登记业务模块 |

实际白名单以公共类型和模块实现为准。未定义模块不会作为合法调用方出现。

## 6. 失败语义

- deadline 在外部调用前后均检查。
- 接收成功不等于执行成功。
- 超时但已可靠提交时返回 pending receipt。
- 副作用未知时返回 `Unknown`，不重放。
- 对用户错误信息进行清洗；内部错误通过 trace 和 exception 查询。
