# 数据日志与异常管理

## 1. DataLog

DataLog 管理事件、审计、指标、trace 索引和应急摘要。输入批次必须携带 producer endpoint、producer epoch、连续 sequence 和 checksum。

耐久等级：

- D0：允许丢弃的诊断数据。
- D1：内存接收。
- D2：写入 journal。
- D3：文件同步。
- D4：带可信锚点的防篡改证据。

高等级写入失败不能降级为成功。D4 需要平台 TPM/HSM 或远端 witness；参考实现仅提供可注入边界和测试 Provider。

## 2. 隐私

- 用户原文、完整地址、凭证和未脱敏 Provider payload 禁止进入通用日志。
- payload 采用封闭 JSON 形状和大小上限。
- trace 查询受调用方、范围和分页上限控制。
- audit hash chain 和 anchor generation 用于检测回滚或篡改。

## 3. Exception

Exception Manager 负责：

- 异常字段归一和脱敏。
- occurrence 幂等账本。
- fingerprint 分组。
- 生命周期和 reopen。
- 升级策略与 storm control。
- journal、snapshot 和应急环。

异常报告保留 request、trace、plan、execution 和 producer 因果身份，但不暴露原始敏感内容。

## 4. 联合关系

- 普通业务模块同时写事件和异常。
- Exception 的审计事件进入 DataLog。
- DataLog 自身故障通过有界 emergency ring 记录，避免无限递归。
- `Unknown` 副作用以 Critical/SafetyAffected 形状上报。

## 5. 恢复

重启时检查 frame、checksum、sequence、commit 绑定和 hash chain。可识别的 torn tail 可修复；已提交中段损坏、回滚或错误 transaction 绑定必须失败关闭。
