# 构建、运行与测试

## 1. CMake 目标

- `MasterAgent::Core`：公共静态库目标。
- `master_agent_app`：默认应用目标，输出文件名为 `master_agent`。
- `memory_short_term_core`：随包提供的短期记忆实现。

主要选项：

```text
MASTER_AGENT_BUILD_APP=ON
MASTER_AGENT_BUILD_TESTS=ON
MASTER_AGENT_ENABLE_IPC=OFF
MASTER_AGENT_ENABLE_QNN=OFF
```

## 2. 本机构建

```powershell
cmake -S . -B build -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DMASTER_AGENT_BUILD_APP=ON `
  -DMASTER_AGENT_BUILD_TESTS=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

运行：

```powershell
.\build\master_agent.exe `
  --runtime=.\runtime `
  "请把空调切换到内循环"
```

输出为 JSON，包含 TurnResult、plan 状态和 Mock 模型调用轨迹。

## 3. Android arm64

使用 NDK toolchain：

```powershell
cmake -S . -B build-android-arm64 -G Ninja `
  -DCMAKE_TOOLCHAIN_FILE=<NDK>\build\cmake\android.toolchain.cmake `
  -DANDROID_ABI=arm64-v8a `
  -DANDROID_PLATFORM=android-28 `
  -DANDROID_STL=c++_static `
  -DMASTER_AGENT_BUILD_TESTS=ON
cmake --build build-android-arm64 --parallel
```

`scripts/deploy_android.ps1` 默认只构建并推送。只有显式传入 `-RunSmokeTest` 才会在指定设备运行一次 Mock 流程。

## 4. 测试分组

| 目标 | 重点 |
| --- | --- |
| test_e2e | 接入、记忆、确定性任务、两阶段 Mock、重启 |
| test_atomic | MCP、并发、优先级、抢占、幂等、Unknown |
| test_atomic_durability | invocation seal、重启、损坏恢复 |
| test_orchestrator_durability | WAL、终态重放、失败关闭 |
| test_inference | Replica、KV、P0/P2 抢占、取消、恶意输出 |
| test_observability | 日志、审计、异常、隐私、D4、恢复 |
| test_resilience | deadline、资源、回调和故障注入 |
| test_contracts | 跨模块身份、schema 和 caller whitelist |
| test_mcp_wire_contracts | MCP JSON-RPC 线协议 |
| test_prompt_skill | Prompt 模板选择/渲染、Skill 配置加载/路由/正文披露 |
| test_preprocess | UTF-8、参数、时间、保留字段、状态能力/查询和可观测依赖 |
| test_memory_short_term_l1 | 同事提供的 L1 原始测试，测试源码不作修改 |
| test_ipc | 可选 IPC transport；默认不构建 |

## 5. 单模块与全流程

运行单个测试：

```powershell
ctest --test-dir build -R test_inference --output-on-failure
```

运行全部：

```powershell
ctest --test-dir build --output-on-failure
```

交付判定至少包括：干净配置、全量编译、自动测试、安装包 consumer 构建、静态命名和注释检查、清单哈希验证。Android 交叉编译成功不等同于真实车辆或真实模型验证。
