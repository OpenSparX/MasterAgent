# 单进程与线程模型

## 1. 默认选择

当前默认形态是单进程。该选择减少部署、权限、IPC、故障恢复和客户调试成本，适合先验证 Master Agent 的业务闭环。

单进程不等于取消模块边界。每个模块仍通过公共接口、调用方白名单、稳定 ID、deadline、幂等键和状态机隔离。

## 2. Owner 执行模型

| 区域 | 当前实现 |
| --- | --- |
| Interaction / AgentService | 由接入调用线程驱动；同一用户会话在 TurnID 分配前串行化 |
| Orchestrator | `pumpOne()` 每次推进一个受控状态转换 |
| AtomicService | `pumpOne()` 推进一个原子执行或对账转换 |
| Inference | `pumpOne()` 推进一个作业、Replica 或 KV 转换 |
| AgentDispatch | `pumpOne()` 推进一个调度或 Provider 转换 |
| DataLog / Exception | 独立写入锁和持久化边界 |
| Optional IPC | 启用时使用有界 mailbox 和 worker thread |

参考应用同步驱动 Owner 循环，以保证 Mock 测试可重复。公共实现是线程安全的，集成方可以把不同 Owner 循环绑定到专用线程，但同一模块的业务状态仍只能通过该模块状态机修改。

## 3. 锁与外部调用

- 锁只保护内存状态和短小的状态转换。
- 模型、KV Provider、车辆 Provider 和子 Agent 回调不得在状态锁内执行。
- 外部调用前创建 invocation seal；返回后重新校验 epoch、fencing、lease 和状态。
- 旧回调不能覆盖更新的取消、抢占或恢复结果。
- 同一会话串行，不同会话可由宿主并发调用。

## 4. 优先级

统一优先级为：

- `P0`：安全或系统关键任务。必须由可信授权产生，模型不能自行提升。
- `P1`：当前前台交互和一般用户任务。
- `P2`：后台、预取或可延迟工作。

队列比较先看优先级，再看 deadline，最后看入队序号，保证稳定顺序。

## 5. 抢占

抢占是协作式状态转换：

1. 高优先级任务进入。
2. 调度器选择允许抢占的低优先级 victim。
3. 增加 `control_epoch` 并发出抢占请求。
4. victim 在工具或模型定义的安全点保存状态、释放资源。
5. 新任务获得资源。
6. victim 只有在 fencing 和 lease 仍有效时才可恢复。

系统不使用强制终止线程。若外部副作用已经开始且结果不可判定，状态进入 `Unknown` 并转入对账。

## 6. 后续多进程扩展

若模型隔离、车辆权限或故障域要求增强，可在保持接口不变的前提下启用 IPC Adapter。建议先按 Core、Inference、Capability 三个进程拆分，不建议恢复为大量细粒度进程作为默认形态。
