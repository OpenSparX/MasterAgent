【适用场景】
当用户表达车内闷、不舒服、热、冷、空气差、想舒服一点等主观体感诉求时，使用本 Skill。

【触发信号】
用户表达包含但不限于：
1. 有点闷，帮我舒服点。
2. 车里不太舒服。
3. 空气不太好。
4. 稍微调舒服一点。

【目标】
围绕座舱舒适度，判断可能相关的调节方向，并输出舒适性调整建议或执行思路。

【输入关注点】
1. 用户在描述温度、空气、风量、风向还是噪声问题。
2. 是否有特定乘员或区域受影响。
3. 当前更适合直接建议还是先澄清。
4. 是否存在儿童、老人、睡眠中乘员等特殊情况。

【执行步骤】
1. 提取用户的主观体感问题。
2. 判断最可能相关的座舱调节项，如空调、风量、风向、内外循环、车窗。
3. 如果 query 过于模糊，先提出最小必要澄清。
4. 如果可以做默认解释，则输出温和、保守的舒适性调整建议。
5. 如果存在特定乘员限制，应提示避免影响其舒适与安全。

【分支处理】
1. 表达“闷”时，优先考虑通风、循环、风量、车窗。
2. 表达“冷/热”时，优先考虑温度与风量。
3. 如果 query 同时包含情绪色彩，应保持安抚式表述。

【约束】
1. 不假设底层能力一定可执行。
2. 不输出过度激进的调节建议。
3. 驾驶安全优先，不建议明显分散注意力的复杂操作。

【输出要求】
输出至少包括：
1. 当前理解到的体感问题。
2. 推荐关注的调节项。
3. 建议动作或需澄清的问题。

【终止条件】
当舒适性建议或必要澄清已经给出后结束。

【失败与回退】
若完全无法判断用户不适来源，则回退为简短澄清。
